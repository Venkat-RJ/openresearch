# Problem Description

A project consists of a set of real activities numbered from one through the total number of real activities, plus two fictitious activities that represent the project start and project end. The project-start activity is numbered zero, and the project-end activity is numbered one more than the total number of real activities. The complete set of activities therefore runs from zero through one more than the total number of real activities. Each real activity has a known integer processing time and is non-interruptible, meaning once started it runs continuously for its full duration. The two fictitious activities have zero processing time and consume no resources.

The project uses a set of partially renewable resources. Unlike conventional renewable resources whose capacity refreshes every period, each partially renewable resource has its availability restricted to a specified subset of periods drawn from the planning horizon, which runs from period one through a prescribed maximum project duration. Each resource has a known integer capacity that limits the total consumption across all activities over the resource's designated period subset. For each real activity and each partially renewable resource, a per-period resource demand is given as a nonnegative integer. When an activity with a given start time is in execution during periods that belong to a particular resource's designated period subset, the number of such overlapping periods is counted; the activity's total consumption of that resource equals this overlap count multiplied by its per-period demand for that resource. Specifically, an activity started at some time is considered to be in execution during the half-open interval from strictly after its start time up to and including its start time plus its processing time, and the overlap is determined by intersecting this interval with the resource's period subset. The sum of these consumption values across all activities must not exceed the resource's capacity.

General temporal requirements govern the sequencing relationships between pairs of activities. For each such pair, a time lag is specified as an integer that may be positive, zero, or negative. When the time lag is positive, the second activity in the pair must start no earlier than the specified lag after the first activity starts. When the time lag is negative, its absolute value acts as a maximum time lag, requiring that the second activity starts no later than that many time units after the first activity starts. In all cases, the start time of the second activity minus the start time of the first must be at least the specified time lag. The maximum project duration is enforced by including a temporal requirement from the project-end activity to the project-start activity with a time lag equal to the negative of the prescribed maximum project duration.

The project-start activity must begin at time zero. All activity start times must be nonnegative integers. The planner must choose a start time for every activity such that all temporal requirements between activity pairs are respected, the total consumption of each partially renewable resource across all activities does not exceed its capacity, and the start time of the project-end activity is as small as possible. The goal is to minimize the project duration, which equals the start time of the project-end activity.

The input data for an instance specifies the number of real activities, the prescribed maximum project duration, the processing time and per-period resource demand for each activity and each partially renewable resource, the set of pairs subject to temporal requirements together with their time lags, and for each partially renewable resource its capacity and the subset of periods during which it is available.

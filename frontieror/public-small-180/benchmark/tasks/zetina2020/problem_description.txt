# Problem Description

This benchmark comprises two classical combinatorial optimization problems — the Maximum Cut (MaxCut) problem and the Travelling Salesman Problem (TSP). Each instance is one of the two problem types, defined purely in business terms below.

In the MaxCut problem, an undirected graph is given with a set of nodes and a set of edges connecting pairs of nodes. Each edge may carry a weight; in the benchmark instances all edges are unweighted (weight one). Every node must be assigned to one of exactly two subsets, so that the node set is partitioned into two groups. The goal is to maximize the total weight of edges whose two endpoints belong to different subsets (the "cut" edges). There are no other restrictions: every assignment of nodes to the two subsets is feasible. The large benchmark instances stored here have 182 nodes and 4,000 edges and use several recorded random-graph generators (fixed-edge Erdős–Rényi, trimmed Barabási–Albert, and a two-block stochastic block model); the exact graph type and seed are recorded in each instance.

In the Travelling Salesman Problem, a salesman must visit each of N cities exactly once and return to the starting city, forming a closed tour (Hamiltonian cycle) of minimum total travel distance. The input specifies the number of cities and a symmetric distance matrix giving the Euclidean distance between every pair of cities, computed from two-dimensional coordinates uniformly distributed in the unit square. A feasible tour is a permutation of the cities; its cost is the sum of distances between consecutive cities in the permutation, including the distance from the last city back to the first. The objective is to choose the permutation that minimizes this total tour length. Benchmark TSP instances use four cities.
